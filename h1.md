# SSH public key - Login without password
## Lähde: [terokarvinen.com](https://terokarvinen.com/ssh-public-key-login-without-password/)
SSH tekee etäyhteyden otosta helpompaa sekä turvallisempaa, sillä salasanoja ei tarvitse erikseen syöttää jokaisen toiminnon yhteydessä.
SSH-yhteys asennetaan seuraavilla komennoilla:

  ```
  sudo apt-get update
  sudo apt-get -y install ssh
  sudo systemctl enable --now ssh
  ```
Viimeisen komennon enable asettaa SSH daemonin käynnistymään laitteen uudelleenkäynnsityksen yhteydessä ja --now-komento käynnistää sen heti, vaatimatta uudelleenkäynnistystä.
Komento w oli itselleni uusi, se listaa kaikki koneeseen kirjautuneet käyttäjät, mitä he tekevät ja järjestelmän resurssien käytön.
```
ssh keygen -> Luo avainparin, jota käytetään ssh-yhteyden muodostamiseen.
```
Sivun lopussa annetut vinkit ongelmien ratkaisuun olivat itselleni uusia:
```
sudo journalctl --follow -> näyttää viimeisimmät systemd-lokimerkinnät ja tulostaa uusia niiden muodostuessa.
sudo systemctl status ssh -> näyttää SSH:n tilan, kuten onko se käynnissä ja käynnistyykö se automaattisesti bootin yhteydessä.
```
Jäin miettimään, että tämä tehtävä olisi paras kokeilla VPS:n kanssa sillä en ihan hahmota missä 'koneessa' olen, kaikki tapahtuu saman VirtualBoxin Debianin sisällä.

# Hello Ansible
## Lähde: [terokarvinen.com](https://terokarvinen.com/hello-ansible/)
Heti alussa mainitaan, että koska SSH daemonia käytetään samalla host-koneella, ei muodostu erillisiä host- ja worker-koneita.
Ansiblen lingossa host-kone on controller, joka käy järkeen koska vain pääkoneelle asennetaan Ansible ja sen koodit, jotka se ajaa alikoneille.
```
sudo apt-get update
sudo apt-get install ansible micro bash-completion tree
```
Sivun ohjeissa nostetaan, että vain Ansible tarvitaan sen toimimiseen, mutta oheissäädökset tekevät sen käytöstä helpompaa.  
Micro: tekstieditori  
Bash-completion: tabulaattorin tekstin täydennys  
Tree: hakemistopuu  

Ansiblelle luodaan .ini-tiedostoilla hallittavat **hostit**, joille voidaan ajaa komentoja ja ryhmitellä niitä niiden tehtävien mukaan.  
**Playbook** on .yml-tiedosto, joka listaa, mitä tehdään ja mille koneille.  
Playbook koostuu **tehtävistä (Tasks)**, jotka hyödyntävät **moduuleja**, kuten **apt, copy, user.**  
**Roolit (Roles)** paketoivat kansioihin kokonaisuuksia. Esimerkiksi nginx-rooli luodaan kerran, jonka jälkeen sitä voidaan hyödyntää eri Playbookeissa.  
Ohjeessa nostetaan lisää "Quality of Lfe"-säädöksiä, jotka otan käyttöön itse tehtävässä.

## d) Hei Ansible
Aloitin Ansiblen asennuksella:
```
sudo apt-get update
sudo apt-get install ansible micro bash-completion tree
```
Sitten tein Teron ohjeista poikkeavasti ssh config-tiedoston (kumppanini ohjeiden avulla)
Kirjoitin: 
```
nano .ssh/config
```
Ja muokkasin sinne tiedot:
```
Host musamasa
    HostName 192.168.1.229
    user musamasa
    IdentityFile ~/.ssh/id_ed25519
    StrictHostKeyChecking accept-new
```
Tämän tiedoston avulla SSH-yhteydelle määritetään oma alias, jolloin voin kirjoittaa vain ssh musama, ilman IP-osoiterimpsua.  
HostName: kohdekone  
User: kohdekoneen käyttäjänimi, muuten koittaisi ssh-yhteyttä nykyisellä käyttäjänimellä (aurisnauris)  
IdentityFile: yksityinen avaimeni tunnistautumiseen ilman salasanaa. Vastaava julkinen avain löytyy kohdekoneelta, .pub-päätteinen, ja viety kohdekoneelle komennolla ssh-copy-id.   
StrictHostKeyChecking: ohittaisi mahdollisen ensimmäisen kerran kyselyn. Jos palvelimen avain muuttuu, tulee ilmoitus **WARNING: REMOTE HOST IDENTIFICATION HAS CHANGED!** ja yhteys katkeaa. Tämä vähentää man-in-the-middle-hyökkäysten riskiä, eli jos joku yrittäisi esiintyä koneena.

## Site.yml
Määritellään mitkä koneet (hosts) saa mitkäkin konfiguraatiot (roles)
```
micro site.yml

- hosts: all
  roles:
    - hello
```
